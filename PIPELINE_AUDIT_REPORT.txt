DETAILED STAGE DOCUMENTATION:
-----------------------------

Stage 1: Audio Input (audio)
- Purpose: Ingest narration audio, validate encoding/size, downsample to 16 kHz mono WAV, initialize project metadata.
- Trigger: HTTP upload to POST /uploads/audio or POST /projects/new.
- Handlers: backend/routes/uploads.py:receive and backend/store.py:new_project.
- Inputs: Audio stream; reads file magic bytes, duration, audio channel configuration.
- Processing: Validates extension (.mp3, .wav, .m4a), converts to 16 kHz mono WAV via ffmpeg, records sha1 in .audio.sha1, writes project.json (aspect: 16:9, use_images: false, motion_branch: true).
- Nature: Pure deterministic code utilizing ffmpeg / ffprobe. No LLM.
- Outputs: audio.mp3, audio_16k.wav, .audio.sha1, project.json.
- Exit Conditions: audio.mp3 and audio_16k.wav exist and pass ffprobe check.
- Consumer: Audio Analyzer.
- Requirement: Mandatory.

Stage 2: Audio Analyzer (analyzer)
- Purpose: Transcribe speech with word-level timestamps, apply LLM correction for domain vocabulary and ASR slips, detect pauses/cuts, compute energy/speech metrics.
- Trigger: Auto-queued on upload or POST /projects/{pid}/run (step transcribe).
- Handlers: backend/pipeline.py steps transcribe, refine, cuts.
- Inputs: audio_16k.wav, optional vocabulary.txt.
- Processing:
  1. transcribe: faster-whisper runs on audio_16k.wav to produce raw word timestamps.
  2. refine: flags low-confidence words, invokes Claude CLI (promptgen.run_claude) to check and correct vocabulary without altering timestamps.
  3. cuts: silence detection via ffmpeg/librosa (SILENCE_MIN = 0.4s, SILENCE_DB = -32dB) into cuts.json.
  4. audio_analysis.py: evaluates 14 audio metrics into audio_analysis.json.
- Nature: Local ML model (faster-whisper) + Claude LLM + deterministic signal processing.
- Outputs: transcript.json, transcript_review.json, transcript_corrected.json, cuts.json, audio_analysis.json, asr_llm_cache.json.
- Exit Conditions: transcript.json and cuts.json exist, LLM verification succeeds.
- Consumer: Scene Segmentation.
- Requirement: Mandatory.

Stage 3: Scene Segmentation (segmentation)
- Purpose: Group continuous narration into coherent semantic scenes based on acoustic pauses and thematic boundaries.
- Trigger: Explicit user click: POST /projects/{pid}/segmentation/run.
- Handler: backend/scene_segmentation.py:run via pipeline step segment.
- Inputs: transcript.json (or transcript_corrected.json), audio_analysis.json.
- Processing: Evaluates acoustic pauses, invokes Claude LLM to propose semantic scene chunks, snaps boundaries to exact spoken words, enforces min/max duration (3.0s - 12.0s), validates zero gaps/overlaps.
- Nature: Hybrid: Claude LLM + deterministic boundary snapping and interval validation.
- Outputs: scene_segmentation.json, scene_llm_cache.json.
- Exit Conditions: scene_segmentation.json validation.status == "ok".
- Consumer: Visual Planning.
- Requirement: Mandatory.

Stage 4: Visual Planning (planning)
- Purpose: Translate narration to English, define per-scene visual concepts, specify text overlays and graphics, author Remotion pattern mappings and image prompts.
- Trigger: Explicit user click: POST /projects/{pid}/visual-planning/run.
- Handlers: backend/autoplan.py:_plan & backend/visual_planning.py:assemble.
- Inputs: scene_segmentation.json, transcript.json, cuts.json.
- Processing: Translates Telugu lines to English via Claude LLM (translation.json, transcript_en.json), compiles plan_input.txt, invokes Claude LLM with PLAN_SYSTEM prompt, evaluates 8 validation passes, formats prompts.txt and prompts_map.json.
- Nature: Claude LLM (promptgen.run_claude) + strict Python schema validation.
- Outputs: translation.json, transcript_en.json, plan_input.txt, scene_plan.json, prompts_map.json, prompts.txt, visual_planning.json.
- Exit Conditions: scene_plan.json, prompts_map.json, visual_planning.json exist with 0 blocking errors.
- Consumer: Motion Planning (and Asset Collection when images are used).
- Requirement: Mandatory.

Stage 5: Motion Planning (motion_plan)
- Purpose: Select animation presets, typography styles, graphic elements, layout zones, camera pans/zooms, and transition styles for every scene.
- Trigger: Advance in Motion-Only mode or POST /projects/{pid}/motion-planning/run.
- Handlers: remotion/scripts/build_composition.ts --plan-only and backend/motion_planning.py:build.
- Inputs: scene_plan.json, visual_planning.json, motion_fixes.json, audio.mp3, remotion/src digest.
- Processing: Runs build_composition.ts to draft motion_plan.json, resolves element requests to registry presets (Tabler icons, chart styles), converts seconds to frames (fr = floor(sec * fps + 0.5)), computes safe area coordinates, margins, z-order, emphasis sync.
- Nature: Pure deterministic TypeScript and Python algorithms. No LLM.
- Outputs: motion_plan.json, motion_planning.json, .motion_checks.json.
- Exit Conditions: motion_planning.json validation passes with 0 blocking errors.
- Consumer: Motion Generation.
- Requirement: Mandatory.

Stage 6: Motion Generation (motion_gen)
- Purpose: Construct the complete Remotion composition.json descriptor hierarchy, verify build determinism, validate layer parameters, record generation audit report.
- Trigger: POST /projects/{pid}/motion-generation/run (pipeline step motion-build).
- Handlers: remotion/scripts/build_composition.ts and backend/motion_gen_report.py:build.
- Inputs: motion_plan.json, motion_planning.json, scene_plan.json, audio.mp3.
- Processing: Runs build_composition.ts twice to verify byte-for-byte determinism, verifies layers match planned presets, injects audio metadata, runs 13 validation stages in motion_gen_report.py.
- Nature: Deterministic TypeScript compiler and Python verification engine. No LLM.
- Outputs: composition.json, motion_generation.json.
- Exit Conditions: composition.json matches motion_plan.json and motion_generation.json records 0 errors.
- Consumer: Motion & Timeline Validation.
- Requirement: Mandatory.

Stage 7: Motion & Timeline Validation (motion_validation)
- Purpose: Pre-build safety gate (Stage 10). Validates that motion outputs conform to design, readability, collision, and timing rules before timeline assembly.
- Trigger: Explicit POST /projects/{pid}/motion-timeline-validation/run or step motion-validate in timeline build chain.
- Handlers: backend/motion_validation.py:run and backend/motion_validation_preview.py:generate.
- Inputs: project.json, scene_segmentation.json, visual_planning.json, motion_plan.json, motion_planning.json, motion_generation.json, composition.json, motion_fixes.json, audio.mp3, transcript.json.
- Processing: Evaluates 12 inspection stages (Input Provenance, Freshness, Scene Mapping, Timing Integrity, Element Completeness, Preset Validity, Layout & Collision, Audio/Text Sync, Transition Readiness, Buildability, Preview Validation, Readiness Gate). Checks for un-rendered required elements; renders preview stills via Remotion Puppeteer bundle into motion_validation_preview/.
- Nature: Deterministic Python rule engine + headless Chrome still renderer. No LLM.
- Outputs: motion_timeline_validation.json, motion_validation_preview/manifest.json and PNG stills.
- Exit Conditions: Report status is ready or ready_with_warnings.
- Consumer: Timeline Build.
- Requirement: Mandatory gate for Timeline Build.

Stage 8: Timeline Build (timeline)
- Purpose: Compile scene-based composition.json into continuous, track-based timeline.json snapshot with validated intervals, layers, and transition envelopes.
- Trigger: POST /projects/{pid}/timeline-build/run or pipeline step timeline-build.
- Handlers: backend/timeline_build.py:run and _publish.
- Inputs: composition.json, motion_timeline_validation.json, scene_plan.json, audio.mp3, remotion/src digest.
- Processing: Verifies Stage 10 readiness gate, maps scenes to track clips with half-open frame intervals [start_frame, end_frame), assembles video and audio tracks, calculates transition windows and pause gaps (hold_previous_scene), validates structural integrity, performs atomic publish (backs up prior timeline to timeline_backup/).
- Nature: Pure deterministic Python assembly and validation engine. No LLM.
- Outputs: timeline.json, timeline_build_report.json, timeline_build_attempt.json, timeline_backup/.
- Exit Conditions: timeline.json published, report status completed or completed_with_warnings.
- Consumer: Timeline Approval.
- Requirement: Mandatory.

Stage 9: Timeline Approval (approval)
- Purpose: Stage 12 human governance gate. Certifies that a specific, immutable fingerprint of the timeline has been reviewed and approved for video encoding.
- Trigger: User click Approve on Timeline Approval page (POST /projects/{pid}/timeline-approval/decision).
- Handler: backend/timeline_approval.py:decide.
- Inputs: timeline.json, timeline_build_report.json, motion_validation_preview/, user decision payload (expected_fingerprint, decision_by, warning_acknowledgements).
- Processing: Re-computes current timeline version fingerprint, ensures project is idle with 0 blocking errors, verifies all warnings/approximations have explicit acknowledgements, checks review coverage, appends immutable decision to timeline_approval_history.json.
- Nature: Deterministic Python state machine recording human approval. No LLM.
- Outputs: timeline_approval_history.json, timeline_review.json.
- Exit Conditions: Active approved decision matching current timeline fingerprint recorded.
- Consumer: Render Video.
- Requirement: Mandatory gate for final render.

Stage 10: Render Video (render)
- Purpose: Stage 13: Render approved composition into a verified MP4 video using Remotion and headless Chromium.
- Trigger: POST /projects/{pid}/render.
- Handlers: backend/render_video.py:run executing Remotion via backend/render.py:render.
- Inputs: composition.json, timeline.json, timeline_approval_history.json, audio.mp3, Remotion configurations.
- Processing: Verifies approval gate, writes render_manifest.json, stages audio, executes npx remotion render, probes output via ffprobe / media_probe.py (checks H.264, dimensions, 30 fps, duration tolerance +/-0.15s, audio stream), publishes atomically to out.mp4, writes render_report.json.
- Nature: Remotion (Node.js/Puppeteer/Chromium) + ffmpeg + deterministic Python wrapper. No LLM.
- Outputs: out.mp4, render_manifest.json, render_job.json, render_report.json, render_profile.json.
- Exit Conditions: out.mp4 passes all media verification checks, render_report.json published.
- Consumer: Final QC.
- Requirement: Mandatory to produce video.

Stage 11: Final QC (qc)
- Purpose: Stage 14: Quality control inspection combining automated glitch detection with human review.
- Trigger: POST /projects/{pid}/final-qc/run + POST /projects/{pid}/final-qc/review.
- Handlers: backend/final_qc.py:run and review.
- Inputs: out.mp4, render_report.json, composition.json, timeline.json.
- Processing: Probes out.mp4 for frozen frames, dropped frames, black frames, audio clipping, loudness metrics. Extracts keyframes to qc_frames/*.jpg. Records findings into final_qc_report.json. Accepts human sign-off confirming playback verification with sound.
- Nature: Automated ffmpeg inspection + human review decision. No LLM.
- Outputs: final_qc_report.json, qc_frames/*.jpg.
- Exit Conditions: Automated checks pass and human records approval for exact video SHA-256.
- Consumer: Final Video.
- Requirement: Mandatory.

Stage 12: Final Video (final)
- Purpose: Delivery gate presenting finalized video for download or playback on dashboard.
- Trigger: Implicit query evaluation when final_qc_report.json approval gate is satisfied.
- Handler: backend/pipeline_view.py:build.
- Inputs: out.mp4, final_qc_report.json.
- Processing: Confirms out.mp4 exists on disk and has an approved QC decision matching its SHA-256.
- Nature: Read-only query.
- Outputs: Verified, downloadable out.mp4.
- Exit Conditions: out.mp4 is certified by Final QC.
- Consumer: User / Client.
- Requirement: Terminal stage.

3. THE MOTION PIPELINE SPECIFICS
--------------------------------------------------------------------------------

DATA FLOW:
Visual Planning JSON -> Motion Planning JSON -> Motion Generation descriptors JSON ->
Reusable React Component Props -> Motion & Timeline Validation -> Timeline Build ->
Timeline Approval -> Render Video (Remotion + Chromium) -> Final MP4

CRITICAL ARCHITECTURAL DISTINCTIONS:
1. Planning JSON (visual_planning.json & scene_plan.json):
   High-level semantic specifications. Contains scene objectives, visual metaphors, text hints,
   and rough animation concepts ("fade and scale", "slide left"). No concrete frame numbers,
   no Remotion props, no code.

2. Motion Planning JSON (motion_plan.json & motion_planning.json):
   Bridges visual plan to motion engine. Resolves visual items into library component/preset IDs
   (e.g., icon.tabler.eyeglass, typewriter). Converts seconds into discrete frame intervals at
   30 fps: fr = floor(sec * 30 + 0.5). Calculates safe area bounds, z-indices, emphasis word timing.

3. Motion Generation Descriptors JSON (composition.json & motion_generation.json):
   Hierarchical descriptor tree. Each scene contains ordered layer descriptors:
   - motion_text layers (preset, text, font, size, x, y, enter_frame, exit_frame)
   - motion_scene layers with items (preset, props, coordinates)
   - background look and color gradients
   - camera motion transforms (zoom, move)
   - audio reference

4. Code Generation vs. Reusable Components (Crucial Finding):
   SOURCE CODE VERIFICATION CONFIRMS: Motion Generation DOES NOT generate executable
   TypeScript or React (.tsx) code.
   Instead, Remotion contains pre-existing, reusable React animation components:
   - remotion/src/components/Background.tsx (gradient, mesh, spotlight, aurora shaders)
   - remotion/src/components/Chart.tsx (bar, line, pie SVG charts)
   - remotion/src/components/IconPop.tsx (Tabler/Lucide icons with entry animations)
   - remotion/src/components/ShapeAnim.tsx (geometric badges, callouts, cards)
   - remotion/src/motion/text.tsx & compose.tsx (kinetic typography presets)
   During preview or render, Remotion dynamically reads composition.json descriptors and passes
   the fields directly as props to these existing React components.

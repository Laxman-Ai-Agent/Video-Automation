# M4 — Planning: /plan, scene_plan, composition, prompts
Model: Opus for the /plan prompt design, Sonnet for the validators and file writers.
Goal: transcript + cuts -> four Phase 1 files, validated. Claude reads TEXT only, once.

## Tasks
1. `backend/models.py`: pydantic models for scene_plan, prompts_map, composition, layers (mirror `schemas.md`).
2. `backend/validate.py <project>`: validates all JSON files; prints short, actionable errors.
3. `.claude/commands/plan.md`: the /plan command (see below). Keep under 80 lines.
4. `backend/prompts_writer.py`: builds `prompts.txt` (numbered, blank-line separated) from `prompts_map.json`.
   Appends style suffix and ratio; adds white-background phrase for icon/object roles.
5. `backend/plan_checks.py`: automatic quality checks (below) run after /plan.
6. Compact input builder `backend/plan_input.py`: merges transcript + cuts into one short text file
   (`plan_input.txt`: scene candidates with time ranges and Telugu text) to cut tokens.
7. Add `tests/fixtures/plan_sample/` with a known-good example output.

## /plan command behaviour
1. Read only `plan_input.txt`, `docs/schemas.md`, pattern table in `docs/components.md`.
2. Divide into scenes by meaning using cuts from cuts.json (merge small ones; never invent cut times).
3. For each scene decide: mode, pattern, camera, layers, keyword highlights, transition.
4. Write prompts only for images that add value. Typical scene: 0-3 images; some 4-5; some none.
5. Style: define one `style.suffix` and palette for the whole video, appended to every prompt.
6. Write `scene_plan.json`, `composition.json` (image `file:null`), `prompts_map.json`; run
   `plan_checks.py` and `validate.py`, fix issues, then run `prompts_writer.py`.
7. Reply with a 10-line summary: scenes count, images count, modes used, warnings.

## Planning rules (enforced by plan_checks.py)
| Check | Rule |
|-------|------|
| scene length | 3-15 s typical; flag < 2 s or > 20 s |
| coverage | scenes cover 0..duration with no gaps/overlaps |
| text density | <= 2 text elements per scene |
| transitions | no equal consecutive transitions |
| patterns | name exists in components.md |
| timing | all `at` inside scene range |
| prompts | English only, no Telugu script, no "text in image" requests |
| numbers | counter/chart values appear in the transcript; else flagged `approximate` |
| images | total prompts <= 1.5 x scenes (typical) to keep the user's work reasonable |
| icons | icon/object prompts include "isolated on plain white background" |

## Prompt writing guidance for /plan
- Describe subject, setting, light, camera angle, mood; one clear subject per prompt.
- Ratios: main/background 16:9, supporting 4:3 or 16:9, icons/objects 1:1.
- Maps: stylized map prompt only when a real SVG map is not enough; prefer `MapLayer`.
- Avoid real people's names/logos; avoid text, numbers, watermarks inside images.
- Keep style consistent via the shared suffix; do not restyle per scene.

## User review points (show in chat, short)
1. Scene list (id, time, one-line meaning). User may ask to merge/split.
2. After approval, tell the user: "prompts.txt is ready; generate images and upload".

## Done when
- `validate.py` passes; `plan_checks.py` has no errors.
- prompts.txt opens as plain numbered prompts; prompts_map.json has one entry per number.
- Re-running /plan on the same input after edits changes only what was asked.

## Decided with the user (2026-10-26, evening): media design and what was built
- **Goal (user's words):** every video is 100% motion graphics with animation; images and videos are used INSIDE that motion, in ANY amount ("unlimited"), no share to reach. So the per-project shares (default 60/30/10) were removed everywhere: `media_kinds.normalise/options` keep only `ai_images`, no `allowed()`, the upload form sends only `ai_images` (`AiPicturesOption.tsx` replaced `MediaMixPicker.tsx`), the planner is no longer re-asked to hit a mix, `media_mix` only reports what the plan carries, `MAX_REAL_PER_SCENE` is 6 (the clutter limit), the LLM review and step-check prompts no longer judge a share. Old projects keep their stored shares, which are ignored; the plan fingerprint still hashes the stored `media` so their plans stay valid.
- The planner prompt rewrite ("100% Kinetic Motion Graphics", media inside cards / bento grids / device frames) that someone else had started was finished and kept; the Wikipedia `reference` guidance it had dropped was put back.
- **Visual Planning:** a scene's warnings now carry their step number (`validation_notes[].stage`); `fix_warnings(stage=n)` / `start_fix(stage=n)` solve only that step's warnings.
- **Subtasks UI/API:** while a stage runs, its report written before the run started is never shown (`pipeline_view.run_started_at`, `routes/pipeline.py: get_stage_subtasks`); `POST /stages/{stage}/subtasks/{n}/retry` runs one subtask again (Visual Planning step with warnings: solve its warnings; any other step: its LLM check only, `step_llm_check.recheck`); the subtask modal has a "Retry this subtask" button. Steps still running are never sent to the LLM check (`_recorded`).
- **Asset Collection** now writes a live step report `asset_collection_report.json` (5 steps, real counts, per-step `evidence`, `reuse_proof` when the last result is reused); `pipeline_view._assets_stage` shows the stage "running" with its own percent while its run is alive. `step_llm_check` knows the stage (`STEP_REPORTS`, `build_step_evidence`, guidance).
- **Manual uploads (the Asset Collection page) are valid provenance:** the upload now records `source_url: user-upload://<file>` and `authenticity: "user_provided"`; `asset_collection.has_provenance` / `AUTHENTICITY` are the ONE definition (also used by `artifact_contracts.validate_assets_artifacts`), and entries stored before (empty source, `selected_by: manual_upload`) pass too. Before, four hand uploads made the stage fail with "source or licence is missing" x4. Every picture requirement now has a prompt for an image generator (`asset_collection.picture_prompt`: the planner's own, else written from the query and the scene's need); the page shows it with a Copy button, a requirement nobody fills falls back to motion graphics.
- **Why the Asset Collection collected 0 of 4 photos on the test project:** Pexels, Pixabay and Unsplash need API keys (`PEXELS_API_KEY`, `PIXABAY_API_KEY`, `UNSPLASH_ACCESS_KEY`) that are not set; only NASA, Wikimedia and Openverse (no key) work and rarely have lifestyle stock photos. Set the keys for real photos/clips; without them every requirement falls back to generated motion graphics (recorded, not an error).
